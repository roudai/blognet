# Feature Specification: 記事ページとトップページの移植

**Feature Branch**: `002-posts`

**Created**: 2026-11-22

**Status**: Draft

**Input**: User description: "現行サイトの記事ページ5件(`/post-37`、`/post-386`、`/post-388`、`/post-535`、`/post-700`)と、トップページの記事一覧を、001 のサイト基盤の上に移植する。本文、画像、YouTube の動画、ツイートの埋め込みを、現行と同じ URL、同じ内容、同じ見た目で再現する。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 記事を現行と同じ URL で読める (Priority: P1)

訪問者は、検索結果や外部のリンクから、現行と同じ URL(`/post-37` など)で記事を開き、現行と同じ本文(見出し、段落、リスト、手順の枠、投稿日と最終修正日)を読める。

**Why this priority**: サイトの価値は記事の本文であり、既存の URL を維持すること(原則 II)が移行の最重要条件である。

**Independent Test**: 5件の記事の URL を開き、本文のテキストとリンク先が、現行サイトと一致することを確認する(記録済みの誤字の修正を除く)。

**Acceptance Scenarios**:

1. **Given** 訪問者が `/post-37` を開く、**When** ページが表示される、**Then** 現行と同じ見出し、投稿日、最終修正日、本文、リンクが表示される。
2. **Given** 訪問者が `/post-37/`(末尾のスラッシュあり)を開く、**When** ページが表示される、**Then** 同じ記事が表示される。
3. **Given** 5件のいずれかの記事、**When** 現行サイトと本文を比べる、**Then** テキストとリンク先の相違は、この Spec に記録した修正だけである。

---

### User Story 2 - 画像、動画、ツイートが記事の中で表示される (Priority: P1)

訪問者は、記事の中の画像(キューブの図、写真)、YouTube の動画、ツイートを、現行と同じ位置と大きさで見られる。動画はページ内で再生できる。

**Why this priority**: 記事の多くは、画像や動画を前提に説明しており、それらがないと内容が伝わらない。

**Independent Test**: `/post-37`(画像、動画、ツイート)、`/post-535`(ツイート)、`/post-700`(写真)を開き、すべての画像、動画、ツイートが表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 訪問者が `/post-700` を開く、**When** ページを最後までスクロールする、**Then** 8枚の写真が、現行と同じ位置と幅で表示される。
2. **Given** 訪問者が `/post-37` を開く、**When** 動画の埋め込みを再生する、**Then** ページ内で YouTube の動画が再生される。
3. **Given** 訪問者が `/post-535` を直接開く、**When** ページの表示が終わる、**Then** 6件のツイートが埋め込みとして表示される。
4. **Given** 訪問者がトップページから記事へ移動する(ページの再読み込みなし)、**When** 記事が表示される、**Then** ツイートが埋め込みとして表示される。

---

### User Story 3 - トップページから記事を選べる (Priority: P2)

訪問者は、トップページ(`/`)で、現行と同じ見出しと、5件の記事へのリンクを、現行と同じ順序で見られる。リンクを選ぶと、その記事へ移動できる。

**Why this priority**: サイト内の回遊の起点だが、記事そのものが先に移植されている必要がある。

**Independent Test**: `/` を開き、見出しと5件のリンク(表示名とリンク先)が現行と同じ順序で並び、それぞれの記事へ移動できることを確認する。

**Acceptance Scenarios**:

1. **Given** 訪問者が `/` を開く、**When** ページが表示される、**Then** 見出し「ブログ版ろーだいねっとアーカイブ」と、5件の記事へのリンクが現行と同じ順序で表示される。
2. **Given** 訪問者がリンクを選ぶ、**When** 移動する、**Then** 対応する記事が表示される。

---

### User Story 4 - 明らかな誤字が直っている (Priority: P3)

訪問者は、現行の記事にある明らかな誤字(英単語の綴り、人名の綴り、改行で分かれた語)が直った本文を読める。直した箇所は、この Spec の「現行の表記から直した箇所」に記録されている。

**Why this priority**: Constitution の原則 IV の例外で許されている改善で、パリティの確認と同時に行える。必須ではない。

**Independent Test**: 記録した各箇所が、修正後の表記になっていることを確認する。

**Acceptance Scenarios**:

1. **Given** 記録した修正の箇所、**When** 新サイトの記事を見る、**Then** 修正後の表記になっている。
2. **Given** 記録した修正以外の箇所、**When** 現行サイトと比べる、**Then** 表記は同じである。

---

### Edge Cases

- ツイートの読み込みに失敗した場合(ネットワークや、ツイートの削除): 埋め込みの代わりに、元のリンク(ツイートの URL)を含む引用の要素が残る。ページの他の部分の表示は妨げない。
- 削除されたツイート: 現行サイトでも「表示できない」状態で表示されるものがある。現行と同じ埋め込みを置くことで、同じ状態にする(新サイトで差し替えない)。
- 画面幅が狭い場合: 画像と動画は本文の幅に収まる(はみ出さない)。
- 現行の記事のリンクの中には、リンク先が存在しないもの(例: URL の代わりに文字列が入っている `href`)や、提供が終わった外部のページがある。原則 IV により、運営者の指示なしには変更せず、候補として記録する。
- 現行サイトでは、記事の中に自動広告が差し込まれている。新サイトでは広告を含めないため(原則 III)、その分だけ縦の位置がずれるが、相違としては扱わない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 記事ページ `/post-37`、`/post-386`、`/post-388`、`/post-535`、`/post-700` とトップページ `/` は、静的生成の出力に、現行と同じパスで含まれなければならない(MUST)。
- **FR-002**: 各記事の本文(見出し、投稿日と最終修正日、段落、リスト、手順の枠、リンク)は、移植元(`legacy/pages/post-*.vue`)と同じでなければならない(MUST)。ただし、「現行の表記から直した箇所」に記録した修正は除く。
- **FR-003**: 記事の画像は、移植元(`legacy/assets/37/`、`legacy/assets/700/`)と内容が同一のファイルを、同じファイル名で、固定の URL(`/images/<記事番号>/<名前>`)から配信しなければならない(MUST。Constitution の Technology & Delivery Constraints)。
- **FR-004**: 画像の表示の大きさと位置(幅の指定、中央寄せの有無)は、現行と同じでなければならない(MUST)。
- **FR-005**: YouTube の動画は、現行と同じ動画を、同じ位置に、本文の幅に合わせた 16:9 の大きさ(最大幅 720px)で埋め込まなければならない(MUST)。ページ内で再生できなければならない(MUST)。
- **FR-006**: ツイートは、現行と同じツイートを、同じ位置に埋め込まなければならない(MUST)。ページを直接開いた場合と、サイト内のリンクで移動した場合の両方で、埋め込みとして表示されなければならない(MUST)。
- **FR-007**: トップページは、現行と同じ見出しと、5件の記事へのリンクを、同じ表示名と順序で表示しなければならない(MUST)。
- **FR-008**: 明らかな誤字の修正は、「現行の表記から直した箇所」に、現行の表記と修正後の表記を記録しなければならない(MUST)。誤字かどうかが明らかでないもの、リンク先の変更、古くなった情報の更新は、直さずに候補として記録する(運営者の指示があるまで変更してはならない。MUST NOT)。
- **FR-009**: ページには、Google 広告を含めてはならない(MUST NOT。原則 III)。
- **FR-010**: `legacy/` 配下のファイルを変更してはならない(MUST NOT)。

### Key Entities *(include if feature involves data)*

- **記事**: 記事番号(URL のパスの一部)、タイトル、投稿日、最終修正日、本文。本文は、段落、見出し、リスト、手順の枠、画像、動画、ツイートからなる。
- **記事の画像**: 記事番号ごとのフォルダーにある webp ファイル。`/post-37` に10枚、`/post-700` に8枚。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 6ページ(トップと記事5件)のすべてで、現行サイトとの本文のテキストとリンク先の相違が、記録した修正を除いて0件である。
- **SC-002**: 18枚の画像のすべてが、移植元と内容が同一で、現行と同じ順序で表示される。
- **SC-003**: YouTube の動画9件とツイート7件のすべてが、現行と同じ位置に埋め込まれ、ページを直接開いた場合とサイト内で移動した場合の両方で表示される。
- **SC-004**: 幅 1280px と 375px で、各記事を現行サイトと並べて比較したとき、見出し、画像、動画、ツイートの大きさと位置に、運営者が気づく相違がない(広告の有無による縦の位置のずれを除く)。
- **SC-005**: 出力に、Google 広告の痕跡が0件である。

## Assumptions

- 現行の内容は、`legacy/pages/` のソースと、公開中の `https://blog.roudai.net` を正とする。両者が異なる場合は、公開中のサイトのブラウザー上の表示を正とする(例: 段落の中に置かれたブロック要素は、ブラウザーが段落を分けて表示している)。
- 記事ごとのページタイトル、OGP、サイトマップ、RSS、記事の Markdown 化は、機能追加にあたるため対象外とする(原則 IV)。
- ツイートと動画は、外部サービス(X / Twitter、YouTube)の埋め込みであり、外部サービス側の表示の変化(削除されたツイートなど)は、パリティの対象外とする。
- 埋め込みの手段(`vue-youtube` の代替、`widgets.js` の読み込み方)は、Plan で決め、原則 VIII のとおり spike で検証する。
